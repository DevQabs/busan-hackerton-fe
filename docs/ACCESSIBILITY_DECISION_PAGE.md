# 접근성 진단 — 페이지 설명

<!-- 반영·검증: 2026-07-26 · [AccessibilityDecisionScene.tsx](../components/scenes/AccessibilityDecisionScene.tsx) -->

내비게이션 2번째 페이지, `PageId = "accessibility-decision"`.
질문: **등록 장애인 및 두리발 이용 대비 생활 인프라 현황.**

하나의 점수로 답하지 않고 **개수**와 **거리** 두 축으로 나눈다. 두 축이 자주
엇갈리고, 그 엇갈림 자체가 결론이다 — 부족의 성격이 다르다는 뜻이기 때문이다.
설계 배경은 [INFRA_METRIC_RETHINK.md](INFRA_METRIC_RETHINK.md).

## 데이터

`disability.json`(등록 장애인·5월 완료 이용, 16 구) · `dongs.geojson`(경계·centroid·
시설 5종, 206 동) · `toilets_gu.json` · `infra_points.json` · `travel_times.json`.
`registered === null`인 구는 제외한다.

원천적으로 불완전해 화면에 명시하는 둘: **장애인화장실**은 좌표가 없어 개수
비교에만 쓰고 점·거리에서 빠진다. **1층 상가**는 확인된 접근성이 아니라 조사
우선순위 프록시(`shops × shopsFloor1Share`).

## 개수 축 — 도시 총량 대비 배분

```
needShare = balanced → (populationShare + tripShare)/2 · population → 인구만 · trips → 이용만
expected  = 시설 유형별 부산 총량 × needShare
ratio     = actual / expected      shortfall = max(0, expected − actual)
```

**100%는 충분성 기준선이 아니라 비례 배분 몫이다.** 부산 전체가 부족하면 모든
구가 100% 근처에 놓인다 — 이 지표는 형평을 재지 필요 충족을 재지 않는다.
비교 대상은 16개 구 평균이 아니라 도시 총량의 비례 몫이라 작은 구에 안정적이고,
`deficitCount`는 유형별로 따로 세어 상계하지 않는다. 옛 `gapScore`는 쓰지 않는다.

지도 색은 미달 개수가 아니라 격차의 깊이를 본다: 75% 미만이 둘 이상이면 빨강,
하나면 노랑, 75~100% 편차가 여럿이면 파랑. 99%와 40%가 같은 신호를 내지 않는다.

## 거리 축 — 가장 가까운 시설까지

206개 동의 centroid 기준. `travel_times.json`이 `ok`면 **분** — 동 안에 시설이
있으면 그 점까지, 아니면 관측된 승차→하차 중앙값, 미관측 쌍만 직선 ÷
`meta.medianKmh`. 아티팩트가 없으면 **직선거리 × 1.3**이고 토글 라벨도
"도달 거리"로 바뀐다. 도로망 그래프는 이 저장소 어디에도 없다.

기본 대상은 충전기·복지 거점뿐이다. 병의원·약국은 거의 모든 동에 있어 206개 중
165개가 500m 안에 들어가 지도가 온통 초록이 된다.

**색은 절대값이 아니라 부산 안에서의 백분위다.** 도시 중앙값이 554m라 절대
임계값을 쓰면 대부분 첫 구간에 몰린다. 빨강은 "2km 초과"가 아니라 "부산 하위
25%"이며, 이렇게 해야 두 지도가 "평균보다 나은가 나쁜가"라는 같은 언어를 쓴다.

## 화면 구성

**컨트롤(좌상단)** 필요의 기준 · 지도 단위 · 시설 · 수요. 거리 지도에서는
화장실·1층 상가를 제공하지 않는다(좌표 없음). **범례(좌하단)** 는 읽기 전용으로
분리해 클릭 요소를 밀어내지 않는다.

**수요 레이어** 는 공급 지도 위에 실제 도착을 얹어 "시설은 여기, 사람은 저기"를
한 화면에 둔다. 하차 히트맵(`trips_anim` 12,000건 표본) 또는 주요 이동 60개
(`od.json` 400쌍에서 동일 동 25개를 빼고 상위 60, 143~31건). 켜면 채움이 45%로
낮아진다. 방향은 화살표가 없어 색 그라데이션으로 읽는다.

**KPI 밴드** 는 도시가 아니라 선택 구를 따라간다. 등록 인구 · 완료 이용 ·
도달 거리 순위(소속 동 백분위 중앙값) · 평균 배분 순위와 진단. 해운대구를
고르면 첫 타일이 상세 페이지 진입 버튼이 된다.

**「필요의 기준」 해석 카드** 가 사이드에 상시 붙는다 — 50:50은 거주 형평과
통행량 어느 쪽에도 치우치지 않는 기본값, 인구만은 호출조차 못 하는 곳을 드러내되
목적지형 지역을 과소평가, 이용만은 실수요를 우선하되 억눌린 수요를 작게 잡는다.
두 비중 차이가 1%p 이상이면 기준을 바꿀 때 순위가 움직인다는 경고가 붙는다.

**하단 띠** 는 진단의 근거 3칸: 필요 비중 분해와 기대량 계산식 · 다섯 시설의
배분 대비 비율 칩 · 도달 거리 중앙값과 가장 먼 동.

## 두 축 진단

`verdictFor(deficitShare, accessPercentile)` — 개수 임계값은 유형의 40%,
거리 임계값은 도시 상위 40%(구는 소속 동 백분위의 중앙값).

| | 가깝다 | 멀다 |
|---|---|---|
| 몫 대비 충분 | 상대적 양호 | **거리 문제** — 증설이 아니라 배치·순회 |
| 몫 대비 부족 | **밀집지 부족** — 기존 거점 수용력 | **이중 공백** — 최우선 |

5월 데이터 검증: **강서구**는 다섯 중 하나만 미달이지만 동이 넓어 중앙값
1,988m·녹산동 5,298m로 도시 최악 → 거리 문제. **중구** 272m, 개수도 몫 근처 →
상대적 양호. **해운대구**는 둘 미달에 중앙값 867m·송정동 2,127m → 이중 공백.
최하위 4분위는 금정·강서·사상·해운대·사하구.

## 서사 2단계

1. **16개 구·군 비교** — 구 지도 + 다섯 유형 막대.
2. **선택 지역 해석** — 필요 비중을 인구·이용으로 분해하고 기대량의 출처를
   보여준다. 이 단계에서 선택 구의 실제 시설 점이 지도에 올라온다.

기존 3단계 「부족 항목 확인」은 해운대 상세 진단의 종합진단으로 옮겼다. 구 단위
논리를 동 단위에 그대로 적용하되(기대량 = 해운대 총량 × 그 동의 호출 비중),
조치 직전 단계는 본선 데이터가 있는 쪽에서만 말한다. 두 화면은 기간·범위·방향이
달라 합치지 않고 페이지 경계에서 갈아끼우며, 진입 버튼 문구가 기준 전환을
명시한다.

## 지도 지오메트리

구 지도에서는 행정동 폴리곤을 구 단위 MultiPolygon으로 합치고 내부 경계를
엣지 dissolve로 제거한다(링 정점 12,730 → 경계 세그먼트 4,077). 동 지도는 반대로
동 폴리곤을 백분위로 칠하고 구 경계를 밝은 선으로 얹는다.

## 파이프라인 — `travel_times.json`

`build_all.py`의 `od_counter` 순회에서 함께 만든다. 양 끝이 행정동에 들어가고
소요가 0~4시간인 완료 운행만, 관측 `TRAVEL_MIN_RIDES = 3` 이상인 쌍만 발행
(분 중앙값·p90·km 중앙값, 상한 `TRAVEL_MAX_PAIRS = 6000`, 버린 양은
`meta.pairsDropped`). 계약은 `TravelTimes`, `validate.py` 검사 7종. 쌍이 없으면
`status: "unavailable"`이며 검증 오류가 아니다.

**실제 데이터로는 아직 돌리지 않았다.** 이 환경에 원시 입력이 없어 합성 입력으로
함수 단위 검증만 했다(임계값·`p90 >= median`·빈 입력 처리, 임시 산출물로
`validate.py` 7종 통과 후 삭제).

## 소리 내어 말할 단서

- 100%는 도시 총량 대비 몫이지 충분성 기준이 아니다.
- 거리는 거주지가 아니라 동 centroid 기준 — 큰 동에서 평탄해진다.
- 직선 × 1.3은 경로가 아니다. 상수라 순위·색에는 영향이 없고 표기만 바뀐다.
- 시간 행렬은 실제 이동이 있던 쌍만, 시간대·요일 구분 없이 쌍당 중앙값 하나.
- 1층 상가는 조사 프록시, 장애인화장실은 구 단위 개수 비교뿐.
- 등록현황 기준일은 구별로 2024~2026년 상이.

## 남은 것

- 원시 데이터가 있는 환경에서 `build_all.py`를 돌려 진짜 `travel_times.json`을
  얻고, 미터가 분으로 바뀌었을 때 구가 진단 칸을 넘나드는지 재확인.
- 진단 임계값 40%/40%는 분포를 보고 고른 값 — 여유가 되면 터사일로 교체.
- `RatioBar`는 0~200% 스케일에 100%가 중앙. 200% 초과는 오른쪽 끝에 붙되 숫자는 남는다.
- 「장애인화장실」이 해운대 상세와 다른 것을 센다(여기는 공공 73곳, 저기는 실사
  309곳) — 라벨에 "공공"을 붙이는 편이 안전하다.
- 본선 해운대 데이터에는 출발 좌표가 없다. 개수 지도는 그대로, 거리 지도는 직선에
  머물고 `travel_times.json`은 비어 honest-degrade가 작동한다.
