# /booking 음성 시연 대본

DIVE 2026 본선. 일반인 발표자가 **화면을 가린 채** `/booking`을 음성만으로 완주하는 1분대
시연. 근거 명세는 `.omc/specs/deep-interview-booking-voice-scope.md`(상위:
`deep-interview-blind-booking.md`).

시간 예산은 **전체 90초, 낭독 1회 35초** (soft). 아래 대본은 실측 약 75초다.

---

## 시작 전 (타이머 밖)

| # | 항목 | 확인 |
|---|---|---|
| 1 | 갤럭시 S26 Ultra + **Chrome**에서 `…/booking?voice=1` 열기 | 상단에 🎤 배너와 `1 / 3 · 출발지`가 보이면 음성 모드 진입 성공 |
| 2 | 마이크 권한 **미리 허용** | 첫 탭에서 권한 팝업이 뜨면 시연 시간이 통째로 날아간다. 리허설 때 한 번 허용해두면 유지된다 |
| 3 | 미디어 볼륨 최대 · 무음/진동 해제 | TTS는 미디어 채널로 나간다 |
| 4 | 화면 밝기 최대 | 소리는 발표자의 것이지만 **화면은 심사위원의 것**이다 |
| 5 | 네트워크 확인 | `SpeechRecognition`은 오디오를 서버로 보낸다. 끊기면 인식이 실패한다 |
| 6 | TalkBack **끄기** | 켜져 있으면 마이크가 TalkBack 낭독을 되받아 오인식한다 |

백업: 맥북 Chrome에서 같은 URL. 동일 빌드로 동작한다.

## 대본

| 시각 | 발표자 | 기기가 내는 소리 |
|---|---|---|
| `0:00` | "지금부터 화면을 보지 않겠습니다." — 화면을 손이나 종이로 가린다 | — |
| `0:08` | **화면 아무 데나 탭** | 🔊 "출발지, 말씀하세요." |
| `0:10` | "센텀삼익아파트" | 🔊 "출발지, 센텀삼익아파트" |
| `0:20` | **탭** | 🔊 "도착지, 말씀하세요." |
| `0:22` | "벡스코" | 🔊 "도착지, 벡스코" |
| `0:32` | **탭** | 🔊 "탑승 시각, 말씀하세요." |
| `0:34` | "아침 열 시" | 🔊 "탑승 시각, 10시" |
| `0:44` | (아무것도 안 함 — 1.2초 뒤 자동 시작) | 🔊 **전체 낭독 약 30초** |
| `1:14` | 화면을 공개한다 | — |
| `1:16` | "방금 들으신 문장이 화면에 그대로 있습니다." | — |

**낭독되는 문장** (실제 값에 따라 숫자만 바뀐다):

> 센텀삼익아파트에서 벡스코로 10시 출발입니다. 예상 대기시간은 약 46분입니다.
> 재송2동 10시 접수 기준이고, 미배차와 취소 비율은 25퍼센트입니다.
> 도착지 주변 접근시설은 장애인 화장실 벡스코메디컬 180미터, 휠체어 충전소 벡스코1 20미터,
> 장애인 주차장 벡스코메디컬 180미터입니다. 다른 종류 시설 3곳이 더 있습니다.
> 도착지 주변 무장애가게는 5곳입니다. 가장 가까운 곳은 낙지볶음개미집, 20미터입니다.

## 조작은 두 가지뿐

| 제스처 | 동작 |
|---|---|
| **짧게 탭** (화면 어디든) | 다음 단계. 세 개가 다 차면 **낭독 다시 듣기** |
| **길게 누르기 0.6초** | 직전 단계를 다시 말한다 |

버튼을 찾을 필요가 없다는 것이 핵심이다 — 화면을 못 보는 사람에게 버튼의 "위치"는
존재하지 않으므로 화면 전체가 조작 면이다.

## 사고 대응

| 증상 | 대응 |
|---|---|
| 장소가 잘못 잡혔다 (복창이 다르다) | **길게 누르기** → 그 단계를 다시 말한다 |
| 🔊 "소리가 들리지 않았습니다" | 그냥 **다시 탭**하고 또렷하게 말한다 |
| 🔊 "마이크 권한이 없습니다" | 시작 전 체크 2번 누락. 우상단 **끄기** → 주소창 자물쇠에서 허용 |
| 🔊 "네트워크 오류로 음성 인식에 실패했습니다" | 홀 네트워크 문제. **끄기** → 일반 모드에서 손으로 입력해 같은 결과를 보여준다 |
| 낭독이 안 나온다 | 미디어 볼륨/무음 확인. 음성 안내 카드의 **다시 듣기** |
| 완전히 꼬였다 | 우상단 **끄기** → 일반 `/booking`으로 복귀. 모든 기능이 그대로 살아 있다 |

## 예상 질의와 답

**"이거 그냥 음성 검색 아닌가요?"**
아닙니다. 음성은 입력만이 아니라 **출력**이 핵심입니다. 화면을 전혀 보지 않고 대기시간과
도착지 접근시설까지 듣고 끝냅니다. 그리고 같은 내용이 `aria-live` 영역으로도 나가므로,
자기 스크린리더를 쓰는 사용자는 앱 음성을 끄고 자기 속도로 들을 수 있습니다.

**"무대 연출 아닌가요? 실제로 접근성이 있습니까?"**
세 가지를 따로 검증했습니다.
- 맥북 Chrome **axe 위반 0건**
- 갤럭시 **TalkBack 실기**로 (앱 음성을 끈 상태에서) 완주 가능
- **키보드만으로** 완주 가능

**"화면에 있는 숫자를 왜 다 읽지 않습니까?"**
의도입니다. 95% 신뢰구간·표본 수·방법론 각주는 **화면에 그대로 있고 심사위원은 눈으로
읽습니다.** 귀로 듣는 사람에게 그 값들은 행동을 바꾸지 않으므로 35초 낭독 예산을 쓰지
않습니다. 반대로 **미배차·취소 비율은 낭독에 넣었습니다** — "차가 아예 안 올 수도 있다"는
것은 통계가 아니라 지금 나갈지 말지를 바꾸는 정보이기 때문입니다.

**"휠체어 항목은 왜 안 쓰나요?"**
이 흐름의 사용자는 시각장애인이고 휠체어 판정은 하지 않습니다. 그래서 낭독도 "이용 가능
N곳" 같은 **판정 표현을 쓰지 않고** 개수만 말합니다 — 하지 않은 검사를 발견인 것처럼
말하지 않기 위해서입니다. 휠체어를 선택하면 그때 판정이 켜지고 낭독도 바뀝니다.

## 리허설 체크

- [ ] 갤럭시에서 `?voice=1` 진입 → 탭 3번으로 완주, **90초 이내** (실측 기록)
- [ ] 낭독 1회 **35초 이내** (실측 기록)
- [ ] 길게 누르기로 직전 단계 재입력 성공
- [ ] 우상단 **끄기** 후 일반 `/booking`에서 업종 칩·스크롤·지도가 정상
- [ ] 안드로이드 Chrome의 인식 시작음이 `"…말씀하세요"`와 겹치는지 확인
      → 겹치면 `PlaceInput`/`TimeField`의 listening 문구를 비운다
- [ ] 맥북 Chrome 백업 경로 동일 빌드로 완주
- [ ] 홀 네트워크에서 인식 성공률 확인 (실패 시 일반 모드 손입력 대본으로 전환)

**아직 미결 (코드 밖):** 갤럭시 화면을 무대 스크린에 올리는 방법(무선 미러링 vs 삼각대
카메라)과 TTS 음성을 장내 스피커로 보내는 경로.
